# Firewalls: ufw, nftables, iptables, firewalld

> Applies to: agent module `fw`. Verification markers: see [README](./README.md).
> References: [ufw(8)](https://manpages.ubuntu.com/manpages/noble/man8/ufw.8.html), [nft(8)](https://www.netfilter.org/projects/nftables/manpage.html), [Docker packet filtering](https://docs.docker.com/engine/network/packet-filtering-firewalls/)

## 1. ufw ✅

| Item | Detail |
|---|---|
| State | `ENABLED=yes|no` in `/etc/ufw/ufw.conf`; `ufw status verbose` shows defaults and rules |
| Rule files | `/etc/ufw/user.rules`, `/etc/ufw/user6.rules` (generated by ufw); `before*.rules`, `after*.rules` (hand-edited hooks) |
| Numbered list | `ufw status numbered` (numbers shift after deletions; never delete by number in batches — re-read after each) |
| Add | `ufw allow proto tcp from 1.2.3.0/24 to any port 443 comment 'panel:<id>'` |
| Delete | `ufw delete allow proto tcp from 1.2.3.0/24 to any port 443` (same spec) |
| Enable | `ufw --force enable` (without `--force` it prompts about SSH) |
| Defaults | `ufw default deny incoming`, `ufw default allow outgoing` |
| Rate limiting | `ufw limit 22/tcp` (6 connections in 30 s per source) |

Backing up ufw for rollback = copying `/etc/ufw/user.rules`, `/etc/ufw/user6.rules`, and `/etc/ufw/ufw.conf`, then `ufw reload` after restoring.

## 2. Docker bypasses ufw ✅

Docker inserts its own iptables rules. Traffic to published ports is DNATed in `PREROUTING` and goes through the `FORWARD` chain, **never reaching ufw's INPUT rules**. A `-p 5432:5432` container is reachable from the internet even with `ufw deny 5432`.

Fixes, in order of preference:

1. **Bind to localhost**: `-p 127.0.0.1:5432:5432` (or `ports: ["127.0.0.1:5432:5432"]` in Compose). Only local processes (e.g. Nginx) can reach it.
2. **`DOCKER-USER` chain**: Docker evaluates `DOCKER-USER` before its own rules and never modifies it. Example: drop external access to published port 5432 except from one network:

   ```bash
   iptables -I DOCKER-USER -i eth0 -p tcp -m conntrack --ctorigdstport 5432 --ctdir ORIGINAL ! -s 10.0.0.0/8 -j DROP
   ```

   Match on `--ctorigdstport` (the port before DNAT), not `--dport`, which sees the container port after DNAT.
3. **[ufw-docker](https://github.com/chaifeng/ufw-docker)**: adds rules to `after.rules` to make ufw govern Docker traffic. Third-party; document, don't install automatically.

## 3. nftables and iptables backends ✅

- Modern distros use `iptables-nft` (iptables syntax, nftables kernel backend). `iptables -V` prints `(nf_tables)` or `(legacy)`.
- Mixing legacy and nft rule sets on one host leads to confusing behavior; read both (`iptables-legacy-save`, `iptables-nft-save`) when diagnosing.
- `nft -j list ruleset` emits JSON (`{"nftables":[{"metainfo":…},{"table":…},{"chain":…},{"rule":…}]}`); far easier to parse than text.
- Docker ≥ 29 can use nftables directly (`firewall-backend: nftables`) ⚠️; then `DOCKER-USER` guidance differs. Detect and show a note.

## 4. firewalld (P2) ✅

- `firewall-cmd --state`, `--get-active-zones`, `--list-all --zone=<z>`.
- Runtime vs permanent: changes without `--permanent` are lost on reload; with `--permanent` they need `--reload`. Our two-phase apply uses runtime changes first, then makes them permanent on confirm.
- Docker creates a `docker` zone and adds its bridge interfaces to it (Docker ≥ 20.10).

## 5. Avoiding lockouts

- Determine the effective SSH port with `sshd -T | grep -i '^port'` (and `ssh.socket` on Ubuntu 24.04; see [systemd-journald.md](./systemd-journald.md) §3).
- Always keep the SSH and panel ports allowed when the default inbound policy is deny.
- The 60 s confirm + 90 s `systemd-run` safety timer in [modules/firewall.md](../modules/firewall.md) §2 is the last line of defense.
- Cloud security groups are a separate layer; the panel cannot see them.

## 6. Pitfalls

| Symptom | Cause | Fix |
|---|---|---|
| Port open despite ufw deny | Docker published port | §2 |
| `ufw enable` hangs in the agent | Interactive prompt | `--force` |
| Rules gone after reboot (iptables) | Rules not persisted | ufw/firewalld persist automatically; raw iptables needs `iptables-persistent`/`netfilter-persistent` (read-only for us anyway) |
| SSH lost after changing its port | Ubuntu socket activation still listens on the old port, or the firewall allows only the old one | Check `ssh.socket`; allow both during migration |
